# Select bindings

Source: `internal/client/dom/elements/bindings/select.js`.

`bind_select_value` synchronizes a single- or multiple-selection `<select>`. Option values may be native string values or compiler/runtime-attached `__value` values, allowing objects and other non-string values.

`select_option` selects matching options using proxy-aware equality. Multiple selects require an array and select every option whose value is included; invalid multiple values produce a warning and leave the DOM unchanged. A single select clears its selection when no option matches, except for the initial mounting case with `undefined`.

The binding reads `:checked` values on `change`, uses `[selected]` during reset, and adopts the initial DOM selection when the model is `undefined`. Its reactive `effect` runs after block updates so options generated by an `{#each}` block are present before selection is applied.

`init_select` installs a `MutationObserver` for option insertion, nested optgroups, and option `value` attribute changes. It reapplies the stored `select.__value` without changing the model; the model remains authoritative unless an explicit selection event occurs.

```mermaid
flowchart TD
  State[get state] --> SelectOption[select_option]
  SelectOption --> Options[option.selected]
  Options --> Observer[MutationObserver]
  Observer --> SelectOption
  Select -->|change/reset| Read[read selected option(s)]
  Read --> Set[set state]
```

Teardown disconnects the observer. The mounting flag distinguishes initial DOM adoption from later model reconciliation.
